# Spacecraft Software Engineer - Lab Workspace

Refonte International Training and Internship Program - Spacecraft Software Engineer track.
Program work by **Ho Manh Tien**.

This repository is the lab workspace and, later, the capstone home for the program. It
follows the structure introduced in Session 2:

```
spacecraft-fsw-lab/
|-- docs/                 # session notes and ECSS / NASA standards references
|-- labs/
|   |-- 01-foundation/    # Sessions 3-4: HK telemetry, requirements, tests, traceability
|   |-- 02-rtos/          # Sessions 5-6: FreeRTOS HK pipeline, IPC, shared resource protection
|   |-- 03-tmtc/          # Sessions 7-8: CCSDS/PUS TM packets, TC parsing, verification
|   |-- 04-obdh/          # Session 9: APID router, packet store, store-and-forward
|   |-- 05-fdir/          # Session 10: health monitors, watchdog, graduated FDIR
|   `-- 06-mbd/           # Session 11: FDIR as a model, generated C, back-to-back tests
|-- .github/workflows/    # Session 12: CI (build, test, sanitizers, static analysis, coverage)
|-- capstone/             # Session 13+: capstone (frozen requirements, scenarios, traceability, src, tests, report)
`-- tools/scripts/        # helper scripts (dependency fetch, build helpers)
```

## Branch policy and commit style

| Practice | Convention |
|---|---|
| Default branch | `main` stays working and reviewable at all times. |
| Feature branches | One branch per lab or task, e.g. `lab/02-rtos-scheduler`. |
| Pull requests | One PR per lab, opened for review. |
| Commit messages | Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`. |

## Building the labs

Each lab under `labs/` is a small set of plain C files buildable with `gcc`. See each lab's
own README for its exact build command. The RTOS labs (`labs/02-rtos/`) additionally depend
on the FreeRTOS kernel, fetched on demand by `tools/scripts/fetch_freertos.sh` (not vendored
into this repo — see that lab's README).

## Testing and CI (Session 12)

```
bash tools/run_tests.sh              # build every lab with -Werror, run every self check
CC=clang bash tools/run_tests.sh     # same with clang
SAN=1 bash tools/run_tests.sh        # same under AddressSanitizer + UBSan
bash tools/coverage.sh               # FDIR line and branch coverage with floors
bash tools/static_analysis.sh        # clang-tidy, any finding fails
bash tools/demo_gates.sh             # proves each gate goes red on an injected fault
bash tools/check_traceability.sh     # lab and capstone requirement traceability (--strict: acceptance)
bash tools/capstone_gates.sh all     # capstone tests, coverage, cppcheck, report
```

`.github/workflows/ci.yml` runs all of these on every push and pull request. What blocks a merge
and why is in `docs/11-ci-vv.md`; the requirement-to-test matrix is
`docs/10-requirements-test-matrix.md` (generated by `tools/check_traceability.py`).
